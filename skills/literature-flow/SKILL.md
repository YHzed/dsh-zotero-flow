# Zotero 文献流

把「找到这篇文献 → 在机构订阅下拿到全文 PDF → 归进指定的 Zotero 分类」做成一条可复现的流水线。

**这个流程要和人配合，不是全自动爬虫。** 卡在人机校验或机构登录上时，正确的动作是停手、告诉用户、等用户做完再继续。

## 何时用

用户说这些话时走本流程：

- 「把这篇文献下下来 / 找一下全文 / 帮我下 PDF」
- 「存进 Zotero」「归到 X 分类」「加到我的 Zotero 库」
- 「从知网 / 万方 / ScienceDirect / IEEE / Springer / Wiley / ACS 取全文」
- 「学校图书馆有订阅，帮我下」

## 人机校验与机构登录：三条硬规则

这三条优先于本文件其余内容。不要为了「把活干完」而绕过它们。

**1. 撞上人机校验就停手，交给用户手工通过。**

页面出现验证码、滑块、点选、Cloudflare 之类的验证时：立刻停下当前步骤，请用户在弹出的机构浏览器窗口里手工过一次，然后等用户回话再继续。不要刷新重试、不要反复打开同一个地址、不要换入口试探、不要尝试自动识别或自动通过验证，也不要注入脚本把自动程序伪装成人。

**2. 不要让自己的操作被站点识别成自动化程序。**

保持像人在浏览的节奏：一次只处理一篇；不要对同一站点并发请求或高频打开同一页面；不要批量抓链接、批量翻页、批量取 PDF；不要自动填账号密码或验证码；不要用无头模式。插件本身给的是有窗口的独立资料目录，照常用它就够了。一旦看到 403 / 429 / 异常跳转 / 验证页，就当作站点已经起疑：停下来把情况说清楚，交给用户，不要硬闯。

**3. 需要机构登录时提醒用户登录一次，然后把这份登录态记住、一直复用。**

- 首次：明确告诉用户「需要在机构浏览器窗口里登录 <机构> 的 <入口>」，等用户确认登录完成再往下做。
- 之后：同一个平台再取全文，默认用户已经登录好。先 `scholar_session action=status`（必要时 `action=goto` 打开该平台页面）核实一下，确认没掉线就直接继续，**不要再要求用户登录一遍**。
- 保住登录态：会话结束时只用 `action=close` 断开 CDP（不关浏览器）；不要主动关掉机构浏览器窗口、不要换资料目录、不要清 cookie。
- 只有确实停在登录页、或用户说会话过期了，才请用户重新登录，然后更新机构登录记录。

## 机构登录记录

机构和平台的登录情况记在插件数据目录下：

- 路径：`%USERPROFILE%\.dsh-zotero-flow\institution-login-record.md`（Windows；其他系统取插件数据目录下的同名文件）。
- 何时读：每次开始文献流之前读一遍，重点在第 3 步之前 —— 用它判断「这个平台是已经登录好的，还是需要提醒用户登录」。
- 何时写：用户完成一次新登录、验证了某个平台的访问权限、或发现某个平台登录态失效时更新。
- 记什么：机构与登录方式（SSO / CARSI / WebVPN）、入口地址、各平台的登录与权限状态、最近一次验证结果、下一步该走哪条路。
- 不记什么：密码、验证码、cookie 值、令牌、学号等凭据。这里只记状态；凭据交给浏览器资料目录自己保管。

## 先分清三种输入

| 手上有什么 | 起手式 |
| --- | --- |
| DOI / 标题 / arXiv 号 | `literature_lookup` → `scholar_download` → `zotero_save` |
| 只有关键词、还没定哪篇 | `literature_lookup`（给标题或关键词，取候选）→ 与用户确认 → 再走上面 |
| 本地已经有一个 PDF 文件 | `zotero_import_pdf`（它自己抠 DOI） |

## 标准流程

0. 读一遍机构登录记录（见上），先知道哪些平台已经登录、哪些平台上次没走通。

1. `zotero_status`
   确认 Zotero 在跑、当前归档目标、浏览器会话状态。若 Zotero 没开，直接告诉用户打开 Zotero 桌面端，不要继续往下做。

2. `literature_lookup`
   给 DOI 最准。返回标题、作者、期刊、年份、DOI，以及开放获取 PDF 直链与出版社归属。
   标题检索可能命中多条，**命中的第一条不一定是用户要的那篇**，多条时要把候选列给用户确认。

3. `scholar_session`
   - `action=start` 打开机构登录窗口。**第一次必须让用户在这个窗口里完成学校登录**（图书馆 SSO / CARSI / WebVPN），登录态存在独立资料目录里，之后一直有效。
   - `action=goto` 打开 DOI 落地页（`url=https://doi.org/<doi>`）或某个站点。
     返回里重点看三个字段：`doi`（页面自报的 DOI，用来核对没跑偏）、`citationPdfUrl`（出版社给的引文 PDF 直链，最可靠）、`pdfLinks`（页面上的 PDF 相关链接）。
   - 页面迹象里出现「需要登录 / 机构入口」时，按第 3 条硬规则办：先看登录记录里这个平台是否已登录；没登录过就提醒用户登录并等确认，登录过就直接继续，别重复打断用户。
   - 出现「人机校验」时按第 1 条硬规则办：停手，请用户手工过一次。

4. `scholar_download`
   - 有 `citationPdfUrl` 或明确的 PDF 链接：直接传 `url`。
   - 没有直链（知网、万方、ProQuest 等）：让用户在浏览器窗口里点「下载全文」，然后**不带 url** 再调用一次，插件会接管下载目录里新出现的 PDF。这时把 `timeoutMs` 放大到 180000 左右。
   - 返回的 `path` 就是后续归档要用的本地路径。浏览器已经落盘时直接复用，不再写一份副本；此时 `saveAs` 不重命名已有文件。
   - 成功后自动关闭本次插件创建的取全文标签页，以及仍停在原地址的关联文献页；不关用户标签页、SSO 页或整个浏览器。失败/验证码页面保留给用户处理。
   - 必须核对目标 DOI/PII；页面中的其他 `View PDF` 可能属于参考文献，不可误取。
   - 返回 `requiresUserAction` 或 403/429/验证码时立刻停手，不换入口、不自动调用 Zotero 全文解析器；等用户确认后继续。

4a. 下载成功后立即精确关页并核验（归档前门槛）
   - 成功判据：PDF 已确认落盘，保留本地路径。随即列出标签页，按本篇精确 PII（ScienceDirect）或完整 DOI/已核对文章 URL，关闭仅属于本篇的文章页及 PDF 页。
   - 关页后必须调用 `scholar_session action=tabs`，确认本篇文章页和 PDF 页全部消失。只有核验通过才归档，归档结果明确后才处理下一篇；逐篇串行，不与下一篇导航并行。
   - 优先核验插件成功下载后的自建页清理；有残留时先核对页面确属本次流程，使用环境中已验证的精确关页能力，否则请用户手工关闭后再列页核验。禁止无参数全清、按站点域名泛关或关闭用户自行打开的页面。
   - 保留浏览器窗口、about:blank、扩展页、机构登录页和待人工处理的验证页。`action=close` 仅断开连接，不算关闭文章页。脚本退出成功或 CLOSED=0 也不能替代标签页核验。
   - 缺少可靠标识、关页失败、列页失败或仍有残留时，报告“PDF 已下载、关页未核验、尚未归档”并停止；复用已下载文件。下载失败、超时、403/429 或人机校验不走成功清理分支，交给用户处理。
   - 完成本流程使用本地 `pdfPath` 归档，避免 `zotero_save pdfUrl` 将下载和归档合并而跳过关页核验。原本已有本地 PDF 且未为其打开文章页的导入不需要额外关页。

5. 归档（代码强制先查重）
   - `zotero_save`：`doi` + 已下载且关页核验通过的 `pdfPath` + `collection` + `tags`。
   - `zotero_import_pdf`：已有本地 PDF、想让它自己抠 DOI 时用。
   - 两个入口默认检索已有书目与文件哈希：唯一可靠的 DOI/标题匹配复用父条目、保留原分类，PDF 缺失才追加；同文件跳过；确认都无匹配才新建。
   - 多候选、身份冲突或库内检索失败时停止并报告；由用户确认已有条目 key 后用 `zotero_attach_pdf`，不能把不确定当作未命中。
   - 本地 API 开启是自动查重的前提；复用条目追加文件还需要 Zotero 10+ 与原生写入授权。成功判据是返回新建、复用或跳过的明确结果；失败时报告已创建但未完成的附件 key。

## 硬约束

**全文权限属于用户的机构会话。** 从 Node 进程直接 fetch 出版社页面，通常拿到的是付费墙、登录页或 403。要全文就只有走浏览器会话这一条路。不要因为 HTTP 抓取失败就断定「这篇下不到」。

**不做反检测规避。** 站点起疑时，正确反应是放慢、交给用户、如实说明，不是想办法骗过检测。不注入脚本改写 `navigator.webdriver` 或指纹、不伪造 UA、不用打码服务、不共享或伪造登录态、不绕访问控制。用真实浏览器 + 用户真实登录态 + 人工过验证，这三样足够；超出这个范围的技巧一律不做。

**Zotero 连接器只能归档到「当前选中的分类」或「最近使用过的分类」。**
`zotero_collections action=targets` 会列出当前可选的目标 id（`L1`、`C12` 这类）。目标不在列表里时的正确反应是：让用户先在 Zotero 左侧点选那个分类，再重试。**不要猜分类 id，也不要用 `zotero_collections action=list` 里的 key 当目标 id** —— 那是本地 API 的 key，不是连接器的 treeViewID。

**中文库基本没有可自动下载的直链。** 知网、万方、ProQuest 学位论文、科学文库、读秀都是 JS 应用，PDF 往往分章节或走专门阅读器。正确做法是打开页面 → 用户点击 → 接管下载目录。把这一步明确交给用户，不要反复重试自动抓取。

**不要自己拼检索 URL。** 各站的查询串形式不一致。用 `library_sites` 里标了「有稳定检索链接」的，其余直接用 DOI 落地页。

**不要重复下载。** 归档前先看下载目录里是否已有同一篇的 PDF。

## 如实报告

失败要分清楚是哪一种，别一律说「完成了」：

| 情况 | 该说的话 |
| --- | --- |
| 条目已入库、PDF 没挂上 | 「条目已经进 Zotero 的 X 分类了，但 PDF 没附上，原因是 …」 |
| 拿不到全文（无订阅 / 检测到付费墙） | 「落地页显示需要订阅/登录，机构会话里可能没有这篇的权限；可以换文献传递或让图书馆代查」 |
| 目标分类定位不到 | 「Zotero 目前只能归档到 A、B；请在 Zotero 里点选目标分类后我重试」 |
| 检测到人机校验 | 「页面出现了人机校验，请在浏览器窗口里手工过一次，然后告诉我继续」 |
| 该平台还没登录 / 登录态失效 | 「<平台> 这边要机构登录，请在机构浏览器窗口里登录 <机构>，登录完告诉我，我接着取这篇」 |
| 已经是登录好的会话 | 直接继续，不要重复问一遍登录；只在确实停在登录页时才找用户 |
| Zotero 没启动 | 「请先打开 Zotero 桌面端」 |

## 元数据质量

- 有 DOI 就一定要用 `literature_lookup` 查，不要凭记忆写标题、作者、年份 —— 记忆里的书目字段经常错。
- DOI 解析不到时（很新的预印本、中文文献），可以只用用户给的标题建条目，并在回复里说明「这条是手工元数据，建议核对」。
- 中文文献用 `extra` 字段保留原始中文出处，方便以后核对。

## 收尾

归档完成后回报三件事：**条目标题 + 落到哪个分类 + PDF 的本地路径**。用户之后可能要用这个路径做别的事（批注、OCR、喂给别的工具）。

顺手更新机构登录记录：这次在哪个平台、用的哪个机构登录态、是直接复用还是用户新登录的。
